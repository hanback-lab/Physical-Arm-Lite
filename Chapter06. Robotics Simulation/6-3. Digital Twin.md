# Digital Twin

디지털 트윈(Digital Twin)은 현실의 물리 시스템을 가상 공간에 대응시켜 표현한 뒤, 그 상태를 지속적으로 반영하고 분석하는 기술입니다. 현실 대상과 연결되어 상태를 반영하고 미래 동작을 예측할 수 있는 가상 대응체라고 불리기도 합니다.

디지털 트윈이 중요한 이유는 현실 시스템을 직접 반복 시험하지 않고도, 가상 환경에서 설계 검토, 상태 분석, 제어 검증, 최적화, 유지보수 계획을 수행할 수 있기 때문입니다. 디지털 트윈은 상태 표시뿐 아니라 더 나은 설계와 운용 조건을 찾는 데 도움을 주며, 로봇 분야에서는 설계, 시험, 커미셔닝, 운영 중 재구성 문제를 다루는 데 유용합니다. 따라서 로봇 공학에서의 디지털 트윈은 “로봇을 화면에 띄워 보는 기술”이 아니라, 실제 로봇 시스템을 가상 환경에서 검증하고 운용 전략을 다듬기 위한 공학적 도구로 볼 수 있습니다.

## 핵심 특징

디지털 트윈의 첫 번째 특징은 동기화(synchronization) 입니다. 디지털 트윈은 물리 대상과 일정한 주기로 정보를 주고받으며, 상태·조건·형상 변화 등을 반영해야 실시간과 대응할 수 있습니다. 따라서 현실 시스템과의 연결이 없는 정적인 CAD 모델이나 단순 시뮬레이션 파일만으로는 보통 완전한 의미의 디지털 트윈이라 보기 어렵습니다.

두 번째 특징은 목적 지향성(fit-for-purpose) 입니다. 모든 디지털 트윈이 동일한 수준의 정밀도를 가질 필요는 없습니다. 왜냐하면 목적에 따라 필요한 정보 내용, 모델의 충실도(fidelity), 동기화 주기가 달라질 수 있기 때문입니다. 예를 들어 교육용 디지털 트윈은 관절 운동과 충돌만 정확하면 충분할 수 있지만, 예지보전용 디지털 트윈은 토크, 진동, 온도, 마모 같은 상태 정보까지 다뤄야 합니다. 

세 번째 특징은 예측과 분석 기능입니다. 예측은 디지털 트윈의 핵심 요소라고 설명하며, 제조용 디지털 트윈은 기술적으로 시뮬레이션, 데이터 분석, 최적화를 통해 상태 진단과 미래 동작 예측을 수행합니다. 따라서 디지털 트윈은 현실을 복사해 두는 데서 끝나는 것이 아니라, “지금 어떤 상태인가”와 “앞으로 어떻게 될 것인가”를 함께 다루는 체계라고 볼 수 있습니다.

## 로봇 시스템 관점에서 본 Digital Twin

설명하기 전 먼저 현실에는 실제 로봇, 그리퍼, 작업 대상, 센서, 작업 공간이 존재한다고 가정합니다. 또한 이에 대응하여 가상 공간에는 로봇 모델, 물체 모델, 환경 모델, 물리 엔진, 센서 모델이 존재한다고 가정합니다. 그리고 양쪽 사이를 ROS 2, 드라이버, 센서 데이터, 제어 명령, 로그 데이터가 연결합니다 마지막으로 사용자는 시뮬레이터나 대시보드를 통해 상태를 확인하고, 제어 전략을 시험하거나 결과를 분석하는 하나의 시스템을 관점으로 들어봅니다.

이 관점에서 보면, 로봇용 디지털 트윈을 만들 때 반드시 포함해야 할 정보는 생각보다 많습니다. 단순한 3D 형상만으로는 부족하고, 최소한 기하 구조, 운동학, 동역학, 제어 입력, 센서 출력, 작업 환경, 물체 상호작용이 포함되어야 합니다. 국제 표준(NIST) 로봇 시스템 디지털 트윈 연구도 로봇 시스템의 여러 차원을 정확히 표현해야 신뢰할 수 있는 가상 복사본이 된다고 강조하고 있습니다.

### Action Graph 소개

Isaac Sim에 배치된 PhysicAI Arm의 관절각을 조작하려면 어떻게 해야할까요? Isaac Sim에는 시뮬레이션의 조건을 다양화시키기 위해 `Action Graph` 라는 기능을 제공합니다. 이 기능은 시뮬레이션 내부의 로직을 코드 없이 구성할 수 있도록 해주는 노드 기반 실행 시스템입니다. 즉 데이터 및 제어 로직을 그래프 형태로 연결해서 동작시키는 비주얼 프로그래밍 도구입니다.

Action Graph는 크게 세 가지 요소로 구성됩니다.

- Node : 하나의 기능 단위
- Edge(Connection) : 노드 간 연결 선, 데이터 및 실행 흐름 전달
- Execution Flow : 그래프 전체의 실행 순서

Action Garph는 기본적으로 이벤트 기반 실행 모델을 따릅니다. 핵심적인 흐름으로는 제일 먼저 이벤트를 발생합니다. 이 때 발생되는 이벤트의 종류는 시뮬레이션 시작 및 매 프레임 Tick 등이 될 수 있습니다. 이벤트가 발생되는 즉시 해당 이벤트 노드를 실행시키고, 연결된 노드들이 순차적으로 실행됩니다. 그 후 데이터가 다음 노드로 전달되면서 연결된 이후 노드들의 동작을 수행시킵니다.

Action Graph에 대한 더 자세한 소개는 아래 링크를 참고하여 주십시오.

- https://docs.omniverse.nvidia.com/extensions/latest/ext_omnigraph.html

### Node 배치 및 Edge 연결

새 Action Graph는 좌측 상단 툴바에서 Create -> Graphs -> Action Graph를 클릭하여 생성할 수 있습니다.

<img src="pds/action_graph_create.png" style="width:65%">

<br>

Action Graph를 생성할 시 Isaac Sim 하단에 Action Graph를 편집할 수 있는 공간이 생성됩니다. 만약 기존에 있던 Action Graph를 수정하고 싶다면 Stage에 있는 Action Graph를 우클릭 하여 'Edit graph' 를 클릭합니다.

<img src="pds/action_graph_edit.png" style="width:65%">

<br>

제일 먼저 시뮬레이션을 시작할 때 이 Graph도 동시에 실행될 수 있도록 'On Playback Tick' 이벤트 노드를 배치합니다. 노드를 배치하는 방법은 그래프 편집기 좌측에 노드 이름을 검색하거나, 대분류에서 Event -> On Playback Tick 을 드래그하여 편집기 안으로 드롭합니다.

<img src="pds/graph_playback_node.png" style="width:65%">

<br>

그 후, PhysicAI Arm 실제 장비에서 발행되는 관절각인 `sensor_msgs/JointState` 구독하기 위해 'ROS2 Subscribe Joint State' 노드를 배치합니다. Isaac ROS2 대분류 밑에 노드가 위치합니다.

<img src="pds/ros2_sub_joint_node.png" style="width:65%">

<br>

그 후, 해당 관절값을 받아서 시뮬레이션 상의 PhysicAI Arm 매니퓰레이터를 실질적으로 제어시킬 'Articulation Controller' 를 배치합니다. 'Isaac Sim' 대분류 밑에 위치합니다.

<img src="pds/articulation_node.png" style="width:65%">

<br>

필요한 모든 노드를 배치하였다면, 아래 사진과 같이 Edge들을 연결시켜줍니다. 연결된 그래프의 Execution Flow는 'On Playback Tick' -> 'ROS2 Subscribe Joint State' -> 'Articulation Controller' 와 같습니다.

### 속성 연결 및 설정

노드 배치 및 Flow 연결이 완료되었으니, 각 노드들에 필요한 설정들을 진행합니다. 먼저 ROS2 노드에서 관절각을 받을 토픽 이름을 설정해줍니다. 그래프 편집기 상에서 'ROS2 Subscribe Joint State'를 클릭하면 각 노드의 속성값을 편집할 수 있는 'Property' 창이 우측에 생성됩니다. 그 후 Inputs -> topicName 항목에 구독할 토픽 이름을 입력합니다. 현재 이 장비는 `/joint_states` 토픽에 각 조인트의 관절각 값을 발행하고 있으니 값을 'joint_state' 라고 입력합니다.

<img src="pds/set_topicname.png" style="width:65%">

<br>

이 후, 구독 받은 각 조인트의 이름 및 관절각 데이터를 'Articulation Controller'에 넘겨주기 위해 아래 사진과 같이 Edge를 연결해줍니다.

<img src="pds/ros_art_edge_connect.png" style="width:65%">

<br>

이 후, 'Articulation Controller' 노드를 클릭한 뒤 Property 창에서 Inputs -> targetPrim 버튼을 클릭합니다. 이 과정은 이 노드가 시뮬레이션 상에 어떤 로봇을 제어할 것인지를 설정해주는 것입니다.

<img src="pds/add_target_prim.png" style="width:65%">

<br>

표시되는 창에서 PhysicAI_Arm-> physicai_arm 을 클릭합니다.

<img src="pds/prim_select.png" style="width:65%">

### 실행

Isaac Sim 좌측 'Run' 버튼을 눌러 시뮬레이션을 동작시킵니다. 실제 PhysicAI Arm 매니퓰레이터의 움직임과 동일하게 시뮬레이션 상에서 동작하는 것을 확인할 수 있습니다.
